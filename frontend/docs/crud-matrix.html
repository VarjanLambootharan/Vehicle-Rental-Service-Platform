Additional authentication, shared and detail pages

Customer create is POST /auth/registeron the additional Registration page, which does not count among the three member pages. Login uses POST /auth/loginand session bootstrap uses GET /auth/me. Other additional screens include home, customer/admin dashboards, vehicle details, booking details/date edit, payment details, review edit, fleet administration, notifications, forbidden and not-found pages.

Unsupported operations are not marked complete

  • No admin-side customer creation/profile edit, password change/reset, refresh tokens or server token revocation.
  • No physical deletion for customers, vehicles, bookings, payments, maintenance or reviews; the UI uses accurate lifecycle labels.
  • No standalone refund, real gateway, credit-card capture or payment-amount editing.
  • No maintenance vehicle reassignment or editing completed/in-progress details. Transitions follow the backend model.
  • No review restoration, multiple reviews per booking or administrator comment editing.
  • No media upload, pickup-location selection, server pagination, blocked-date calendar or statistics endpoints. See README for frontend handling.

“Connected” describes implemented source/API integration. Actual test coverage and any outstanding verification limits are recorded separately in verification.md.
